## المرحلة 0 — ما نُفّذ

- تعطيل `incremental` في إعدادات بناء API و`database`، وتوجيه البناء إلى إعدادات مستقلة، مع تجاهل ملفات `*.tsbuildinfo`.
- توجيه `main` و`types` و`exports` لحزمة `@rihal/database` إلى `dist`، وربط API بخدمة قاعدة البيانات المشتركة.
- إضافة Vitest واختبارات فعلية للحزمتين؛ `pnpm test` يشغّلها دون تخزين مؤقت، ويفشل عند عدم العثور على ملفات اختبارات.
- توسيع CI بالترتيب المطلوب: التثبيت، توليد Prisma، lint، typecheck، build، test، فحص `apps/api/dist/main.js`، ثم تدقيق تبعيات الإنتاج.
- تحديث تبعيات الإنتاج والتجاوزات اللازمة لاجتياز `pnpm audit --prod`.

## التحقق المحلي

- `pnpm install --frozen-lockfile` — نجح.
- `pnpm lint` — نجح.
- `pnpm typecheck` — نجح، ويشمل ملفات الاختبارات.
- `pnpm build` مرتين مع إجبار إعادة البناء — نجح في المرتين؛ وُجد `apps/api/dist/main.js` و`packages/database/dist/index.js` بعد كل تشغيل.
- `pnpm test` — نجح: 3 اختبارات API واختبار قاعدة البيانات (4 إجمالًا).
- اختبار Vitest بمجلد فارغ — خرج برمز غير صفري كما هو مطلوب.
- `test -s apps/api/dist/main.js` — نجح.
- `pnpm audit --prod` — لم يجد ثغرات معروفة في تبعيات الإنتاج.
- `git diff --check` — نجح.

## المؤجّل والمخاطر المتبقية

- `pnpm db:generate` تعذّر بسبب منع الاتصال بـ`binaries.prisma.sh` لتنزيل `schema-engine`؛ انتهى الطلب بانقطاع TLS قبل التوليد. هذا قيد شبكة في بيئة التنفيذ، وليس فشلًا في اختبار المشروع. البديل: تشغيل الأمر على runner يستطيع الوصول إلى مضيف Prisma، ثم انتظار نجاح بقية خطوات CI.
- لم يُشغّل GitHub Actions عن بُعد، لذا لا تُعد المرحلة 0 مكتملة حتى ينجح توليد Prisma وسير CI كاملًا.
- التدقيق الكامل `pnpm audit`، بخلاف `pnpm audit --prod` المحدد للـCI، أظهر 4 تنبيهات في تبعيات التطوير لـ`fast-uri` (2 متوسطة و2 منخفضة). تُراجع ضمن المرحلة 1.
- لم يبدأ تنفيذ المراحل 1–7؛ لا تبدأ مرحلة لاحقة قبل إغلاق بوابة قبول المرحلة 0.
