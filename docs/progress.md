## المرحلة 0 — ما نُفّذ

- تعطيل `incremental` في إعدادات بناء API و`database`، وتوجيه البناء إلى إعدادات مستقلة، مع تجاهل ملفات `*.tsbuildinfo`.
- توجيه `main` و`types` و`exports` لحزمة `@rihal/database` إلى `dist`، وربط API بخدمة قاعدة البيانات المشتركة.
- إضافة Vitest واختبارات فعلية للحزمتين؛ `pnpm test` يشغّلها دون تخزين مؤقت، ويفشل عند عدم العثور على ملفات اختبارات.
- توسيع CI بالترتيب المطلوب: التثبيت، توليد Prisma، lint، typecheck، build، test، فحص `apps/api/dist/main.js`، ثم تدقيق تبعيات الإنتاج.
- تحديث تبعيات الإنتاج والتجاوزات اللازمة لاجتياز `pnpm audit --prod`، ومطابقة نسخة pnpm في CI مع `packageManager` في `package.json` (`9.15.0`).

## المرحلة 1 — التبعيات الأمنية

- قبل التغيير: `pnpm audit --prod` أعاد `No known vulnerabilities found`. التدقيق الكامل `pnpm audit --json` كشف 4 تنبيهات على `fast-uri@3.1.8` في تبعيات أدوات التطوير (2 متوسطة و2 منخفضة، دون تنبيهات عالية أو حرجة). كانت التجاوزات الإنتاجية اللازمة لـ`deepmerge-ts` و`multer` و`qs` قد أُضيفت في المرحلة 0؛ لم يُظهر تدقيق الإنتاج حاجةً إلى ترقيات إنتاج إضافية.
- أُضيف override إلى `fast-uri@3.1.9`، وهو الإصدار المرقّع الموصى به، وحُدّث `pnpm-lock.yaml`؛ تحقّق `pnpm list fast-uri --recursive --depth 20` من الإصدار الجديد في مسارات التبعية.
- أُضيف `.github/dependabot.yml` لتحديث تبعيات npm/pnpm أسبوعيًا.
- أُضيف `.github/workflows/security-audit.yml`: يدقق تبعيات الإنتاج كاملةً، ويفحص جميع التبعيات بعتبة high، ويعمل عند PR وpush إلى `main`، أسبوعيًا كل اثنين 06:00 UTC، ويمكن تشغيله يدويًا.
- بعد التغيير: `pnpm audit --prod` أعاد `No known vulnerabilities found`؛ و`pnpm audit --json` أظهر أصفارًا في جميع درجات الخطورة؛ و`pnpm audit --audit-level=high` نجح دون تنبيهات عالية أو حرجة.

## المرحلة 2 — قاعدة البيانات والمجال

- أُضيف مخطط Prisma وmigration أولية `20261027200000_initial_domain`، مع مفاتيح أجنبية مركبة تربط `tenantId` بالسجل الهدف في عضويات المجموعات والوثائق والفواتير والإشعارات؛ لذلك ترفض قاعدة البيانات الروابط العابرة للوكالات. أضيفت علاقات الإشعار الاختيارية بالمستخدم والمعتمر.
- فُرض قائد نشط واحد على الأكثر لكل مجموعة بفهرس PostgreSQL جزئي، وحُدّ حجم المجموعة داخل معاملة تقفل صفها، مع trigger في قاعدة البيانات يمنع تجاوز السعة عند الكتابة خارج الخدمة.
- أضيفت بنود الفواتير، وربط اختياري بمعتمر مع لقطة اسم العميل، وانتقالات دفع صالحة فقط.
- استُبدل الحذف بالأرشفة وعلاقات `RESTRICT`؛ تُؤرشف سجلات المعتمر التابعة ضمن معاملة. تستخدم الوثائق `storageKey` خاصًا لا رابطًا عامًا. سياسة الاحتفاظ المؤقتة وحدود الإزالة موثقة في `docs/data-retention.md`.
- أُضيفت خدمات المجال للمعتمرين والمجموعات والوثائق والفواتير، مع انتقالات الحالة داخل المعاملات؛ كما أضيف `prisma/seed.ts` ووصلة `db:seed` ببيانات اصطناعية لوكالتين ومستخدمين بأدوار مختلفة ومعتمرين ومجموعات.
- اختبارات PostgreSQL تغطي الروابط العابرة للمستأجرين، علاقات الإشعارات، الأرشفة، انتقالات الوثائق والمعتمرين والفواتير، قائد المجموعة وسعتها. قرارات التنفيذ موثقة في `docs/decisions.md`.

## التحقق المحلي

### تحقق المرحلة 1

- `pnpm install --frozen-lockfile` — نجح والـlockfile متزامن.
- `pnpm audit --prod` — نجح، دون ثغرات معروفة.
- `pnpm audit --json` — نجح؛ صفر تنبيهات `info` أو `low` أو `moderate` أو `high` أو `critical`.
- `pnpm audit --audit-level=high` — نجح.
- `pnpm lint` و`pnpm typecheck` و`pnpm build` — نجحت.
- `pnpm test` — نجح: 3 اختبارات API واختبار قاعدة البيانات (4 إجمالًا).
- `test -s apps/api/dist/main.js` و`git diff --check` — نجحا.

### تحقق المرحلة 2

- `pnpm install --frozen-lockfile --ignore-scripts` و`pnpm lint` و`pnpm test` — نجحت محليًا.
- في التشغيل المحلي: نجحت 6 اختبارات API واختبار قاعدة البيانات، وتُخطيّت اختبارات PostgreSQL الستة لعدم توفر قاعدة بيانات محلية.
- لم يتوفر PostgreSQL أو Docker/Podman محليًا، كما تعذّر تنزيل Prisma engine بسبب قيد اتصال الشبكة؛ لذلك لم تُنفذ محليًا أوامر `prisma generate` أو `prisma migrate reset` أو seed، ولم يُشغّل `pnpm typecheck` أو `pnpm build` لهذه المرحلة. أكمل CI التحقق على PostgreSQL بدلًا من اعتبار الاختبارات المحلية المتخطاة تحققًا لقاعدة البيانات.
