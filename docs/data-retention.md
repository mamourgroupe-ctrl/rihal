# سياسة الاحتفاظ والأرشفة

**الحالة: سياسة تشغيلية مؤقتة؛ يلزم اعتماد مدة الاحتفاظ القانونية قبل الإنتاج.** لا يُفترض هنا وجود مدة نظامية محددة أو تأكيد امتثال قانوني.

## القواعد الحالية

- الحذف المتسلسل غير مستخدم. العلاقات تمنع حذف السجلات التي لها مراجع (`ON DELETE RESTRICT`)، وتستخدم خدمات المجال `archivedAt` لإخراج السجل من المسارات النشطة بدل حذفه.
- أرشفة مجموعة تؤرشف عضوياتها، وأرشفة فاتورة تؤرشف بنودها، داخل معاملة واحدة. الأرشفة ليست حذفًا ولا تمديدًا تلقائيًا لفترة الاحتفاظ.
- تُحفظ الوثائق كمفتاح تخزين خاص (`storageKey`)؛ لا تُحفظ روابط عامة أو دائمة للملفات.
- بيانات البذور للاختبار اصطناعية، وعناوينها ضمن نطاق `.seed.invalid` وأرقام وثائقها تبدأ بـ`SEED-`. قيمة كلمة المرور فيها علامة غير صالحة للمصادقة وليست كلمة مرور أو hash صالحًا.
- سجلات Prisma لا تطبع استعلامات SQL أو معاملاتها في التطوير، لتجنّب تسجيل أرقام الجوازات أو بيانات الوثائق.

## الحذف النهائي وفترة الاحتفاظ

لا توجد مهمة حذف آلي أو مدة احتفاظ محددة في هذه المرحلة. تبقى السجلات المؤرشفة مقيدة عن الاستخدام العادي إلى أن تعتمد الجهة المالكة والمستشار القانوني جدولًا يحدد المدد حسب نوع البيانات والالتزام التعاقدي/النظامي. بعد الاعتماد فقط، يمكن إضافة عملية حذف نهائي مُراجعة ومقيدة بالمستأجر، مع سجل تدقيق واختبار استعادة/تصدير مناسب. لا تُستخدم قاعدة البيانات الإنتاجية لاختبارات البذور.

## عناصر مراجعة قبل الإنتاج

- اعتماد مدة الاحتفاظ لكل من بيانات المعتمرين، الوثائق، الفواتير، حسابات المستخدمين والإشعارات.
- اعتماد طريقة التعامل مع طلبات التصحيح/الحذف والاستثناءات القانونية، وتحديد صلاحية ومن يوافق على الحذف النهائي.
- التأكد من أن أرشفة المستأجر تقيد الوصول إلى جميع سجلاته؛ ضوابط RLS والصلاحيات تُستكمل في المراحل اللاحقة.
